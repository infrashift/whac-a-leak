**Whac-a-Leak** (`whac`) is a secret scanner in pure Go. It finds API keys,
tokens, private keys and passwords in files, staged changes and git history.

Most scanners use a flat list of regexes. Whac-a-Leak writes its rules in
**CUE**. CUE gives each rule a type, layers and its own samples. CUE runs once,
when whac loads the rules. The scan itself is plain Go.

<Aside type="note" title="Release v0.2.0">
The current release is v0.2.0, for Linux and macOS on amd64 and arm64. The 0.x
version means that options and formats can change before 1.0. See
[Getting Started](./getting-started/).
</Aside>

<CardGrid>
	<Card title="Rule samples" icon="approve-check">
		Each rule has `mustMatch` and `mustIgnore` samples. The engine runs them
		at every load. If a sample fails, whac does not load the rules.
	</Card>
	<Card title="Layers" icon="setting">
		The binary contains the builtin rules. Your `.whac/` config dir adds
		layers: new rules, tighter rules, disabled or re-graded rules.
	</Card>
	<Card title="Two-tier engine" icon="rocket">
		One Aho-Corasick keyword pass selects the candidate rules. Only those
		rules run their regex and charset-aware entropy checks.
	</Card>
	<Card title="Structured files" icon="document">
		whac reads YAML, JSON, `.env`, properties and HCL-style files as key
		paths. It finds a password at `database.credentials.password`.
	</Card>
	<Card title="Fingerprint allowlists" icon="seti:lock">
		A `whac1:` fingerprint of the rule and the secret identifies each
		finding. Allowlist entries do not depend on line numbers.
	</Card>
	<Card title="Offline" icon="star">
		whac makes no network calls, sends no telemetry and does not test
		secrets against provider APIs. A secret stays on your machine.
	</Card>
</CardGrid>
